# ψ：wasm 原生的方法链语言

> **状态**：设计草案（假想语言，未实现）。它依据的通用原则在 [现代编程语言设计](../modern-language-design.md)，本文只写这门语言自己的取舍。

**核心命题**：ψ 的全部语义压成两条——调用是「接收者 + 名字 + 声明数量的实参」的步进链，类型是「数据形状 + 标签集合」且没有任何继承链。管道、中缀、运算符、模块都不是独立机制，而是这两条的记法；函数只有块一种值形态，方法永远不是值，因此没有柯里化。这个压缩不只是审美：它同时消掉了偏应用、树模型、LLVM 后端和链接器。

## 定位：三个宿主，一套产物

ψ 的目标不是通用语言，是同一份小产物落进三个宿主：

- **Rust 引擎扩展**：宿主进程内嵌 wasm runtime，脚本编译成 `.wasm` 模块；改脚本 = 重编译 + 重新实例化。
- **浏览器**：同一个 `.wasm`，JS 只提供导入。
- **CLI**：`psi run script.psi`，CLI 自身也是 wasm host。

由此收敛出四条硬约束：

- **产物必须是标准 wasm**（Wasm 3.0 的 GC 类型 + 少量 WASI 导入），不是私有字节码、不捆绑私有运行时。这条是 [编程语言选型](../language-selection.md) 对 MoonBit 的核心批评所在：211B 的产物如果只能在自家运行时里跑，是演示格式，不是交付格式。
- **编译必须全程序、线性、毫秒级**：脚本每次保存都要重来，编译时间直接落在编辑循环里。
- **规格必须小到一个人能读完**：语言里不能有 borrow checker、allocator、GC 实现、链接器、包版本求解。
- **与宿主的边界只能是字节**：跨 wasm 边界可用的只有数值、线性内存和 `externref`，其余一律序列化。

## 名字

**ψ**（psi）：希腊字母里唯一同时挂着两个意象的——ψυχή（呼吸、灵魂），以及量子力学里那个表示振幅的波函数。轻、没有实体，但确实是场里的东西，与 `~/world` 家族的物理量命名（aura、effector、gravity）同域。

命令行与扩展名用 ASCII 转写：`psi run script.psi`。希腊字母在 shell 里打不出来，所以名字在文档与讨论里写 ψ，落盘一律 ASCII。

## 调用：只留一个原语

### 原语

一次调用 = **一个接收者 + 一个方法名 + 声明规定数量的实参**。实参在源码里不加括号，一个 primary 一步。

```
x.trim                  # 零参调用
x.replace "a" "b"       # 两参调用：replace 的声明有两个参数
xs.map {x| x * 2}       # 块是普通实参
```

关键点不是省了括号，而是 **实参不是方法的语法成分，是链上的步**。`.f` 后面紧跟几个实参步，由声明的 arity 决定；给不够就是编译错误，不会产生「半调用」值。

### 文法

```
stmt    = item | assignment | expr
item    = decorator* decl
decorator = '@' name ( '(' expr,* ')' )?      # 声明上的编译期标签，可叠
decl    = let | mut | def | struct | enum | trait | impl | object
body    = '{' (item | variant)* '}'   # 容器体：struct / enum / trait / impl / object
assignment = name '=' expr      # 目标必须是 mut 槽
type    = name ( '<' type,* '>' )? | '[' type ']' | type '+' type | 'dyn' name
expr    = chain ( infix-op chain )*
chain   = primary step* '?'?
step    = '.' name              # 取方法；其后必须紧跟 arity 个实参步
        | primary               # 一个实参
primary = literal | name | path | '(' expr ')' | block | record | '[' expr,* ']'
path    = ':'? seg ( ':' seg )*   # 段序列；前导冒号 = 绝对
seg     = name | int
block   = '{' stmt* '}' | '{' name* '|' stmt* '}'
record  = '{' name ':' expr ( ',' name ':' expr )* '}'
```

`step` 只有两种，都作用于**整条前缀**。分组由声明决定：`.f` 吃掉紧随的 N 个 primary 步（N = f 的 arity），之后的方法步作用在结果上。中间插入方法步、或链在没吃满时结束，都是「参数不足」的编译错误，不是偏应用。

### 三种记法，同一个原语

| 形态 | 写法 | 展开 |
|:--|:--|:--|
| 方法步 | `x.trim` | 零参调用，取结果 |
| 空白实参 | `x.replace "a" "b"` | 链上追加两个 primary 步 |
| 中缀 | `a + b` | `a.+ b`，同一方法，只是符号位置不同 |
| 管道 | 不存在 | 链即管道：`x.f.g` 就是「先 f 后 g」的管道，不另设管道符号 |

### 四条解析规则

- **每步作用于整条前缀**：`x.f` 作用在 `x` 上，`a b` 里的 `b` 作用在 `a` 上。
- **arity 决定消费几个步**：被调用者（方法或块）声明了 N 个参数，就吃掉紧随的 N 个 primary 步；不够是「参数不足」，多出来的步作用在调用结果上。`a b c` 在 `a` 一参时是 `(a b) c`，在 `a` 两参时是一次二元调用。
- **实参是 primary**：name、字面量、括号、块、记录。要传一个完整表达式，写括号。
- **中缀最松**：应用比中缀紧，中缀按首字符定级。

实例（左侧写法 → 右侧唯一读法）：

- `x.f a b`（f 两参）→ 一次二元调用，`a`、`b` 都是实参
- `x.f a b.c`（f 两参）→ `(x.f a b).c`
- `xs.map f.filter p` → `(xs.map f).filter p` —— 链跨过实参继续，这是流畅 API 成立的原因
- `a.x b.y z`（x 两参）→ 编译错误：`x` 只拿到一个实参，`.y` 把它打断了
- `f a.b`（f 一参）→ `(f a).b` —— `.` 永远作用于整条前缀，要传给 `f` 就写 `f (a.b)`
- `a + b c` → `a + (b c)`
- `a + b * c` → `a + (b * c)`（`*` 比 `+` 紧）
- `a + b y {x| x}` → `a + ((b y) {x| x})` —— `y` 是字母名，只能站在实参位
- `a + b ▷ {x| x}` → `(a + b) ▷ {x| x}` —— `▷` 是符号名，进中缀位；首字符落在最低级，所以比 `+` 松
- `f (a + b) c` → `(f (a + b)) c`

同样一串记号，换个拼法就是另一棵树：`y` 用字母写就是实参，换成符号就变成中缀方法。区分不靠上下文，只靠 lexeme。

### 没有柯里化

「多参数 vs 柯里化」的冲突不存在，因为只剩下前者。

- 方法是唯一可调用的声明形式，arity 写在声明里，调用必须给满。
- 偏应用不产生值：`a.x b` 在 `x` 两参时直接报错，不生成闭包。
- 想要「绑了一部分参数的操作」，写块：`{v| a.x b v}`。单参块的参数默认叫 `it`，日常写作 `{it.x b}`。
- 方法不是值：`Io.stdout.println` 单独成不了表达式，要传出去就包成块。
- 高阶方法要的是函数，不是某条链的残段：`d.map (a.x b.y c)` 里括号求出来的是一个值，类型不匹配；要传变换就写 `d.map {it.x b.y c}`。

不做自动柯里化的理由：函数值的唯一用途是被高阶方法当回调消费，而回调的位置在语法上本来就是一个块。让方法在参数不足时自动降级成函数值，换来的只是「少写一层块」，代价是一整套新规则——arity 何时算饱和、链中段冒出半调用值怎么办、错误为何要等到下一条 step 才暴露。这笔交易只在「方法是值、偏应用无处不在」的语言里划算；ψ 里方法不是值，偏应用没有第二处用途。

### 为什么没有具名函数：统一访问

一个点访问 `x.f` 只有一种含义：**取这个成员并求值**。字段就是零参方法，`c.radius` 读它；方法有参数时，后面的步把参数补上。这条让「字段改成计算方法」对调用点透明——没有 getter/setter 分裂，也没有 `.radius` 与 `.radius()` 两种写法要选。

具名函数值会破坏这条。函数值在点上必须是「取值」（`xs.map trim` 传的是函数本身），方法在点上必须是「调用」（`c.area` 拿的是结果）；两个含义占同一个位置，只能靠宿主类型区分——那等于把 `.` 变成必须看类型才能读的符号。

所以方法不是值，函数只有块：块是匿名的，不存在「名字指什么」。代价是回调要写 `{it.trim}`；收益是每个链步的含义只看写法就能定。

这条规则常被当成「逼用户先定义类型」的机制。它不是禁令，是句法梯度：没有自由函数，每次调用就有一个主语位，`user.charge amount` 读着顺，`Payments.charge user amount currency date` 读着别扭——作者可以这么写（模块对象就是接收者），但写的时候自己看得见。流畅风格下参数本来就只有一两个甚至没有，散装参数没有舒服的位置。

### 数据先行的硬杠杆与软杠杆

硬杠杆是语法上能不能做到，ψ 已有三条：

- **类型必填**：没有 `any`、没有隐式转换，`let x = ...` 推不出类型就编译失败，逻辑没有地方寄放。唯一的通用值是 `Json`——它是有名字的普通 enum，不是 `any`，但确实把这道口子软化了一格，见「动态值与路径」。
- **穷尽匹配**：加一个变体，所有 `match` 立刻报错——类型的形状一变，程序骨架被顶出来，「定义好了，形态自动长出来」靠的就是这条。
- **模块级只有声明**：没有顶层可执行语句，代码不能写成流水账，必须有家。

还缺一条：

- **构造受控**：`Circle { radius: ... }` 外部也能写，parse 造出的值和手搓的值同类型，「边界解析一次、内部不再校验」在语法上落不了地。补法是字段默认只在定义它的模块里可构造，外部只能走导出的构造函数。

软杠杆是人体工学梯度，禁函数属于这一类：它把数据放到句首，散参数落到动词后面变别扭。不硬拦，但绕过时作者自己读得到。要不要补上硬的构造受控，见未决问题。

### 尾块不是特殊规则

`xs.map {x| x * 2}` 里的块是 primary，是普通实参，没有「块绑定最近一次调用」这条规则（Ruby 和 Scala 都需要它）。块的三种形态：带 `|` 的按段数列参数；带 `:` 的是记录字面量；其余是块，体里出现 `it` 就是单参块（`it` 即唯一参数），不出现就是零参块 `{ do_thing }`。

### 中缀：方法即运算符，优先级由拼写决定

`+` 就是方法名，`a + b` 是 `a.+ b` 的记法。任何符号名都是合法的方法名，于是**自定义中缀不需要任何声明动作**：定义一个叫 `<+>` 的方法，`a <+> b` 立刻可用，与 `a.<+> b` 完全等价。运算符不是语法类别，是符号名的方法。

两条边界把这件事钉在词法层：

- **符号名能进中缀位，字母名不能**。`a f b` 这个位置已经被空白应用占用（`f a b` 是步进），字母名再进中缀位就产生两读；符号名是另一类 token，不存在歧义。
- **优先级由首字符决定，不由声明决定**。这是整套设计能保持解析自足的关键：解析器只看 lexeme，不看声明、不读导入，fixity resolution 这个阶段整个不存在。OCaml 用的是同一手法。

优先级表（高 → 低）：

| 首字符 | 结合 | 例子 |
|:--|:--|:--|
| `*` `/` `%` | 左 | `a * b % c` |
| `+` `-` | 左 | `a + b - c` |
| `=` `<` `>` `!` | 不可连写 | `a < b`，`a < b < c` 编译错误 |
| `&` | 左 | `a && b` |
| `\|` | 左 | `a \|\| b` |
| 其余符号 | 左 | `a >>= b`、`a @@ b`、`a ▷ b` |

自定义运算符靠首字符选位置：`+>>` 落在加减级，`<*>` 落在比较级（因此不可连写），`@@` 落在最低级。代价是位置由拼写而非语义决定，写 DSL 时要先决定"我这级放哪"。

被否决的三种做法：

- **字母名中缀**（`a y b`）：与空白应用正面冲突，只能靠额外分隔符共存，或者砍掉值的应用语法改成 `f.apply x`。前者是第二种记法，后者把最常用的高阶写法推成链尾方法，两头都不划算。
- **反引号中缀**（Haskell 的 `` a `y` b ``）：能消歧，但为一个糖再引入一种 token 和一套错误信息，与"文法一页写完"冲突。
- **由声明指定优先级**（Haskell 的 fixity declaration）：解析器必须读跨模块声明，解析与加载耦合，线性编译破产。

`=` 只出现在声明与重绑语句里（`let x: T = e`、`x = e`），不是运算符。`-1` 这类负字面量由词法识别：`-` 紧贴数字且处于 primary 位置。

## 声明：三个引导词，类型后置

```
let name: Text = "psi"        # 不可变槽
mut count: Int = 0            # 可重绑槽
def area -> Float = ...       # 方法
def scale k: Float -> Circle = ...   # 多参：写成多段
```

- `def` 的返回类型用 `->`，参数类型跟在参数名后（[现代编程语言设计](../modern-language-design.md) 已论证后置标注与推导顺序一致）。
- body 是单个表达式时写成 `= expr`；有 `let` 或多条语句时写成块 `= { … }`，块的值是最后一个表达式。
- 容器体也是块：`{ }` 里换行分隔成员，与函数体用同一套花括号规则。缩进在 ψ 里不承载语义，只影响可读性，格式化器可以整篇重排。
- 参数按出现顺序逐段声明，段的个数就是 arity；调用时按同一顺序给足。
- `mut` 槽用 `x = e` 重绑；赋值是语句，不是表达式，不出现在链上。
- 类型参数写在名字后：`struct Box<T>`、`def first<T> xs: List<T> -> Option<T>`。
- 没有 `func`、没有 `fn`、没有 `lambda` 关键字：函数只有块字面量一种形态。

### struct / object / 模块是同一个构造

```
struct Circle {
  let radius: Float

  def area -> Float =
    3.14159 * self.radius * self.radius
}

object Geo {
  let unit: Float = 1.0
  def scaled c: Circle k: Float -> Circle =
    Circle { radius: c.radius * k }
}
```

三种容器只有实例数不同：

- `struct`：声明形状，实例任意多个。
- `object`：声明形状并立即绑定唯一实例，名字即那个实例。
- 文件顶层：匿名的 `object`，也就是模块。

于是 `def` 在任何容器里都是同一件事——**容器实例上的方法**。没有自由函数，也就没有「全局函数 vs 结构体方法」的分裂：`println "hi"` 在模块里就是 `self.println "hi"`。`main` 是模块对象上的一个方法，被编译器导出成 wasm export。

### 字段即方法

`let radius: Float` 在 `Circle` 里生成零参方法 `radius`。`c.radius` 和方法调用走同一条名字解析路径，没有 getter/setter 的形态分裂，也没有「属性 vs 方法」的语义裂缝。

### 模块即值

`let Shapes = import "./shapes.psi"`。import 返回被导入文件的模块对象，类型位置上的 `Shapes.Circle` 是这个对象上的类型投影。于是命名空间不是树，是对象链：文件路径仍是树（寻址工具），但名字解析不依赖树（与 [现代编程语言设计](../modern-language-design.md) 的立场一致——树降级为寻址，不再作为复用地基）。

名字解析顺序：局部槽 → 当前容器的 `self` 方法 → 外层容器。循环 import 是编译错误。

## 装饰器：声明上的标签

```
@export("parse")
@deprecated("用 Csv.parse 代替")
def parse line: Text -> Row = ...
```

`@名字` 或 `@名字(实参)`，写在被装饰声明的前一行，可以叠加。**它们不生成代码**：装饰器是编译期标签，改的是编译器怎么处理这条声明，不是把声明包成另一个值。

原因在语言的形状：Python 的装饰器等价于 `f = deco(f)`，前提是方法能被值引用；ψ 里方法不是值，也没有宏，所以「把一段行为包进另一段行为」没有落点。剩下的合法能力只有一条——把意图写进声明，让编译器执行。

v1 的语汇（全部由编译器定义，不能用户扩展）：

- `@export` / `@export("name")`：导出成 wasm export。`main` 仍是默认约定，写了 `@export` 就以它为准。
- `@test`：测试入口，`psi test` 收集，不参与正常导出。
- `@deprecated("理由")`：调用点给出告警，仍可编译。
- `@target("browser" | "cli" | "host")`：只在对应宿主编译时存在；其他宿主引用它即编译错误。三宿主的差异走这条，不走运行时分支。

代价直说：语汇固定，不能当库的扩展点。要用户可定义的包装就得开宏；宏真正贵的地方不是「多一遍编译」，而是展开轮数不定、且能生成声明，把编译时间变成数据相关——那是 ψ 唯一不能接受的成本。

## 类型：标签，不是树

### 三种声明，一种附着

```
struct Reading {          # product
  let label: Text
  let value: Float
}

enum Shape {              # sum
  Circle radius: Float
  Rect w: Float h: Float
}

trait Area {              # 标签：一组方法签名
  def area -> Float
}

impl Area for Shape {     # 唯一附着动作
  def area -> Float = match self {
    Shape.Circle r -> 3.14159 * r * r
    Shape.Rect w h -> w * h
  }
}
```

映射到标签模型：

| 层面 | 树的形态 | ψ |
|:--|:--|:--|
| 类型关系 | 继承链 | `impl` 附着，无链 |
| 方法解析 | 沿父链查找 | `(trait, type)` 二元组查字典 |
| 数据复用 | 继承字段 | struct 组合 + trait 默认实现 |
| 分类 | 一个类占一个位置 | 一个类型带任意多个 trait |
| 命名 | 命名空间树 | 对象链寻址（仅寻址，不承载复用） |

### trait 不引入派发顺序

`trait A: B` 只表示「实现 A 的类型必须同时实现 B」的合取约束，不表示父类型。因此 ψ 没有 `super` 调用、没有 mixin、没有线性化——[现代编程语言设计](../modern-language-design.md) 里 Scala 与 Rust 那条分岔在这里取 Rust 一侧，而且是加强版：连 `super` 的语法都不存在，行为冲突只能显式点名。

`impl` 是唯一挂载点，遵守 orphan rule（trait 或类型至少一个在本地），否则全程序编译也判不出该用哪份实现。

trait 可以带默认实现体，实现者不覆写就沿用。这是 ψ 里唯一的代码复用来源：默认实现只复用方法体、不带字段，复用粒度因此被限制在「一段行为」，而不是「一整个类型连带它的状态」。

### 表达式问题的两轴都开

加一个类型 = 新增 `impl`，已有 trait 不动；加一个 trait = 新增 `impl`，已有类型不动。唯一被迫修改现有代码的地方是穷尽匹配——那正是要的。

### 派发：字典传递

每个泛型方法只编译一份，实现通过 `(trait, 类型或构造子)` 字典查表；全程序可见、接收者类型静态已知时直接消解成函数索引。

不做 monomorphization 的理由是优先级：**编译时间第一约束，二进制体积第二，运行时间第三**。单态化让体积和编译时间随泛型实例数乘积增长，而扩展脚本的规模根本撑不起这笔账。代价是间接调用与跨实例特化缺失——这是显式取舍，不是意外。

`dyn Trait` 是存在类型装箱（一个具体值 + 它的字典），不是子类型关系：没有 upcast 链，也就没有里氏替换可依赖。

### 无 null，错误即值

- `Option<T>` / `Result<T, E>` 是 prelude 里的 enum。
- `match` 对 enum 穷尽，漏一个变体即编译错误。
- `x?` 是 `Result` 传播记法，展开成 `match`，不是异常。

## 泛型与种类

### 泛型：声明点写参数，调用点靠推断

```
struct Box<T> {
  let item: T
}

enum Either<L, R> {
  Left l: L
  Right r: R
}

impl<T: Add> Add for Box<T> {
  def + other: Box<T> -> Box<T> = Box { item: self.item + other.item }
}

object Ids {
  def only<T> x: T -> List<T> = [x]
}
```

- 类型参数写在声明名后，约束写在参数名后：`<T: Add + Ord>`。`trait A: B` 是同一套合取。
- **调用点不写类型实参**。`f<Text>` 与中缀 `<` 在词法上不可分，硬要分就得再发明一个记号；改为双向检查从实参与期望类型推断，推不出来就用带标注的 `let` 固定：`let xs: List<Text> = ...`。
- impl 可以带参数与约束：`impl<T: Add> Add for Box<T>`。
- 派发仍是字典传递，键是 (trait, 具体类型)；泛型方法只编译一份，类型实参在编译期消失。

### 种类：只用来按构造子派发

```
trait Functor<F<_>> {
  def map<A, B> self: F<A> f: Fn<A, B> -> F<B>
  def as<A, B> self: F<A> value: B -> F<B> = self.map {x| value}
}

impl Functor for List {
  def map<A, B> f: Fn<A, B> -> List<B> = ...
}
```

`F<_>` 是种类参数：它接一个构造子，不接一个类型。四条规则把它关在可控范围内：

- **种类不推断**。构造子只能写死在 trait 声明与 impl 目标里；`def` 上不许出现种类参数，否则调用点就得推断构造子，等于引入高阶合一。
- **impl 目标有两种形态**：带实参的类型（`for List<Shape>`）按具体类型实现；不带实参的泛型名（`for List`）按构造子实现，后者只对带种类参数的 trait 合法。
- **构造子来自接收者的静态类型**。`xs.map f` 里 `xs: List<Int>`，先合一外层（F := List），再合一元素（A := Int），最后从 `f` 推 B——一阶合一加一次构造子替换，没有高阶合一。
- **接收者类型可以显式写出**：`self: F<A>`。impl 目标是具体类型时按老规矩省略；按构造子实现时必须由 trait 声明给出。

收益只有一条，但很实在：trait 的默认实现写一次，所有构造子实现继承——`as`、`map2`、`zip_with` 这类派生方法不必每个容器重写一遍。

边界：

- v1 只支持一元构造子。`Map<K, _>` 这种部分应用没有语法，二元容器要么各自声明 `BiFunctor<F<_,_>>`，要么不用 HKT。
- 种类参数不参与推断，所以不能写 `def collapse<F<_>> xs: F<Int>`——那是在 def 上放种类参数。

## 动态值与路径

### Json：边界上的动态值

```
enum Json {
  Null
  Bool b: Bool
  Num n: Float
  Str s: Text
  Arr xs: List<Json>
  Obj m: Map<Text, Json>
}
```

这是 prelude 里的一个普通 enum，不是类型系统里的 `any`：构造、匹配、派发都走普通规则，`match` 照样要穷尽；它也没有点访问动态键的能力（`json.user` 不存在），取键必须走路径。

定位是**边界类型**：外部数据进来 `Json.parse text`（返回 `Result<Json, Text>`），出去 `json.render`。领域类型仍然要自己定义，Json 不参与建模。语言没法强制这条纪律，能做的是让它比定义类型更啰嗦——每次取值返回 `Option`，要自己判。这跟「接收者必是聚合」一样，是软杠杆。

代价两条：`Num` 只能是 `Float`，超过 2^53 的整数丢精度；`Obj` 用无序映射，键序不保留。

命名用 `Json` 不用 `Variant`：文档里「变体」已经专指 enum 的 case（`Shape.Circle` 就是变体），再让一个类型叫 Variant 会天天打架。

### Path：段序列，两个宿主共用

```
let p = user:name
let q = data:0:items        # 整数段是索引
let r = :usr:local:bin      # 前导冒号：绝对路径
```

- `Path` 是段序列，段只有两种：名字或索引。字面量只吃标识符与整数；带点、空格、转义的键写 `Path.of ["a.b"]`，来自外部字符串的路径写 `Path.parse "./data.txt"`。
- 两个消费者：`Json.at p`（键或下标），`Fs.read p`（OS 路径）。渲染成哪个宿主的形状由方法决定：`p.os` 用 `/` 连接，`p.json` 用 `.` 与 `[i]`。
- 做成第一类值的理由：`let key = user:name` 之后可以 `config.at key`、`keys.map {it.name}`——路径能存、能传、能算，不是靠字符串拼。

**不做 JSONPath 的查询子集**。没有 `*`、没有 `..`、没有 `?()` 过滤。理由在类型上：通配符让结果从 `Json` 变成 `List<Json>`，路径就从「定位」变成「查询」，两种语义塞进一个类型，取值处只能猜返回形状。要遍历就先 `match` 出形状再上链：

```
let labels = users:0:labels
match json.at users {
  Some (Json.Arr xs) -> xs.map {it.at labels}
  _ -> []
}
```

若将来确实要通配，那应该是独立的 `Query` 类型，不是 Path 多一个段。

## 组合：链、Fn、合取

组合有三种，拓扑各不相同，不能互相替代。

### 链 = 先后

`xs.map f.filter p` 就是「先 f 后 p」，写法即顺序，语法层免费。这是默认的组合方式，绝大多数场景到此为止，不需要组合子，也不需要 `∘` 运算符。

### Fn = 把一段先后物化成值

需要把变换存起来、传出去、或从两条变换造一条时，用块：

```
let normalize = {it.trim.lower}
xs.map {it.trim.lower}
```

组合是 `Fn` 上的方法，不是独立函数：

```
trait Fn<A, B> {
  def apply arg: A -> B
  def then next: Fn<B, C> -> Fn<A, C> = {x| next.apply (self.apply x)}
}
```

块是 `Fn` 族 trait 的实现者，单参块对应 `Fn<A, B>`，多参块对应多元版本。`xs.map (normalize.then quote)` 把两条变换接成一条。语言里没有 `∘` 运算符：组合是 `Fn` 上的方法，与其他行为一样挂在类型上。

### trait 合取 = 同时具备

合取就是 `trait Duplex: Read + Write`：实现 `Duplex` 的类型必须同时实现 `Read` 与 `Write`。参数类型可以直接写这个合取的名字，也可以就地写 `Read + Write`。产物是约束，不是行为，也不含顺序：合取说的是「这个值同时具备这两面」，不是「先经过这一面」。

关键区分在拓扑：链是复合（f 的输出进 g），trait 是积（一个值同属多个面）。若让 trait 层承担串联，就必须引入「携带上一段结果的能力对象」——那个东西就是 `Fn` 换个名字，还得再定义一次 `apply`。所以 trait 层的组合止于合取，串联的职责归链。

## 一段完整程序

```
enum Shape {
  Circle radius: Float
  Rect w: Float h: Float
}

trait Area {
  def area -> Float
}

impl Area for Shape {
  def area -> Float = match self {
    Shape.Circle r -> 3.14159 * r * r
    Shape.Rect w h -> w * h
  }
}

impl Area for List<Shape> {
  def area -> Float = self.fold 0.0 {acc s| acc + s.area}
}

object Report {
  def line s: Shape -> Text = "area = {s.area}"
}

def main args: List<Text> -> Int = {
  let shapes = [
    Shape.Circle 1.0,
    Shape.Rect 2.0 3.0
  ]
  shapes
    .filter {s| s.area > 2.0}
    .map {it| Report.line it}
    .each {it| Io.stdout.println it}
  shapes.area.println
  0
}
```

续行规则：行尾有未闭合的 `(` `[` `{`，行尾是未完成的中缀运算符或 `=`，或下一行以 `.` 开头时，语句继续；否则换行即语句结束。

### 记法总则

- 调用不带括号：实参是 primary，一个一步，作用于整条前缀。
- 名字即调用：`c.area` 是求值；方法不是值，函数只有块。
- `self` 是当前容器实例；`it` 是单参块的参数；`_` 是通配模式。
- arity 由声明决定，调用必须给满；不够即报错，没有偏应用。
- 类型实参只在声明与 impl 目标里写；调用点靠推断，构造子不进 `def`。
- `:` 只出现在三处：记录字段、类型标注、路径字面量；路径字面量只吃标识符与整数。
- 中缀是记法：符号名可中缀，字母名不行；优先级由首字符决定（`*` `/` `%` > `+` `-` > `= < > !` > `&` > `|` > 其余）。
- 链即管道；`?` 挂在链尾。

早退、`for` 与模式的覆盖范围未定，见未决问题。

## 为什么不需要 LLVM

### wasm 是栈机，所以没有寄存器分配

LLVM 的主要价值在优化（SSA、指令选择、寄存器分配、循环变换），不在「能不能生成机器码」。wasm 的执行模型是显式栈：表达式按后序发射，操作数自然落在栈上，局部变量是索引化的 slot。于是后端退化成「类型化 HIR → 指令序列」的线性化，没有寄存器分配这一阶段，也就没有随之而来的约束求解、活跃区间分析和溢出处理。

这是 ψ 编译快的第一根支柱：**省掉的不是优化质量，是整整一层与目标机耦合的机制**。

### 目标是线性，不是单遍

「单遍」的字面意思是扫一遍源码就出机器码，那是 C 时代流式编译的遗产。它的好处是内存小、无中间表示；代价是硬性的——声明必须先于使用，不能跨声明推断，也不能拿整个程序的信息来决定派发。

ψ 有类型推断，字面上的单遍不可能：至少要先收签名再查体（文件内两遍），再由接收者类型解析 trait、插入字典（按需一次，不迭代）。所以这里的目标改成**线性多遍、无不动点、无优化管线**。真正决定编译时间的是后者，不是遍数：

- **不动点**：推断迭代到收敛、trait 选择互相依赖、宏展开轮数不定——都是「再来一遍直到没变化」，行数一多就爆。ψ 的双向检查每段体走一次，trait 解析按需一次。
- **单态化**：实例数相乘，代码量随调用点增长。ψ 用字典传递，一个泛型方法一份。
- **优化管线**：SSA、内联、循环变换。ψ 全不做。
- **链接**：全程序一个模块，没有对象文件与符号解析。

设计目标（未实现，不作已验证数字）：千行级脚本的全程序编译落在 10 ms 量级，随行数近线性。这个目标靠的是结构而非工程打磨——没有不动点、没有单态化、没有优化器，编译器就没有可以超线性的地方。

### wasm-gc 是必需项，不是可选项

不用 wasm-gc 就要在语言里自己实现分配器、GC、对象布局和逃逸分析——那三样东西恰恰是让「小」破产的源头。用 wasm-gc 后，ψ 的运行时接近零：一个固定长度的 glue（内存读出、字符串视图、宿主导入转发），其余全由宿主承担。

代价明确：依赖宿主支持 GC 类型。GC 已进入 Wasm 3.0 标准（2025-09 完成），Chrome / Firefox 2023 年即默认开启，Safari 跟进较晚，Wasmtime 需要开 `gc` feature。老运行时与部分嵌入式 wasm 引擎跑不了——这正是 [Wasm 统一运行时](../wasm-unified-runtime.md) 说的第二梯队依赖。

### 备选：Cranelift

Cranelift 有 wasm32 后端，技术上可以直接拿来做代码生成，也能省掉自写发射器。不用它的原因不是不能，而是不必要：它是通用优化式 codegen，走了优化器就丢掉「线性、无优化管线」这条主目标，而 ψ 要的正是没有优化器。它只在将来需要 native（非 wasm）产物时才进入选项。

### 对照：本语言 vs 私有运行时

产物 = 标准 wasm 模块 + 标准 GC 类型 + WASI 导入。任何符合 Wasm 3.0 的宿主都能直接实例化，不需要装 ψ 的运行时。这条线就是「格式」与「交付」的分界。

## 内存与值语义

- 值不可变；`mut` 只重绑槽，不改值。聚合的「更新」返回新值。
- 没有引用类型、没有生命周期、没有借用检查、没有所有权转移：闭包按值捕获，跨边界只有字节。
- 核心数组 `[T]` 定长、构造后只读；prelude 的 `List` 是链式持久结构，prepend O(1)、索引 O(n)。
- `"{x}"` 是 Text 插值，展开成 `Text.concat` 链，不引入新的求值机制。
- 状态只有两处：模块级 `mut` 槽（单例状态）与宿主句柄。

代价直说：大数组原地更新是 O(n)，热循环不是 ψ 的场景。它换掉的是 borrow checker 这一整层——对脚本规模的代码，这层成本远大于收益。

## 编译流水线与速度来源

| 阶段 | 做法 | 省掉的东西 |
|:--|:--|:--|
| 词法 | 单遍，仅识别负字面量与换行续行 | — |
| 语法 | 递归下降，步文法无歧义 | 优先级/结合性声明表、fixity resolution |
| 解析 | 局部槽拉平为数组，`self` 链尾递归 | 作用域树遍历 |
| 类型 | 双向检查，期望类型灌入块；种类只做 arity 校验 | 全局合一、rank-2 推断、种类推断、高阶合一 |
| 降级 | 一 `def` 一函数，闭包一 struct | 单态化、内联、装箱优化 |
| 发射 | 直接二进制编码 | LLVM、链接器 |

全程序一个 `.wasm`，没有对象文件、没有单独编译、没有运行时加载 `.psi`。热重载 = 重编译重实例化，这也正好是宿主侧最干净的隔离单位。

## 三个宿主的形态

### CLI

`psi run script.psi`，CLI 是 Rust 二进制 + wasm runtime，编译与实例化在同一次进程内完成。stdin / stdout 是 `Text` 或 `Bytes`，参数是 `List<Text>`。没有 shell 语义：没有内建 `cd`、`ls`、环境变量，这些走宿主导入。

### 浏览器

产出 `.wasm` 加一份几十行的 JS glue：`WebAssembly.instantiateStreaming` + 导入表（`log`、`fetch`、`now`）。GC 类型使值在 JS 侧表现为不透明引用，读写都经过 glue。

### Rust 扩展

宿主内嵌 wasm runtime，实例化脚本模块，调用导出的 `main` 或命名方法。边界是字节：宿主把参数序列化进线性内存，guest 读成 ψ 值，结果按同一格式回写。

为什么边界只能是字节：wasm-gc 的 struct / array 是宿主不透明引用，没有跨边界共享可变对象的办法，而共享本来也不该有——每实例独立堆是「脚本改坏了不崩宿主」的前提。换取隔离的代价是复制，这对扩展脚本的调用频率是可接受的。

## 与 nushell、Scala 的分界

**nushell** 保留的部分：结构化数据、静态类型、方向固定的数据流。改掉的两点正是它自己承认的短板——不能自定义类型（ψ 的核心就是 struct / enum / trait）；管道是「值喂给下一个独立命令」，方法只能是内建的，用户自定义类型拿不到 fluent 语法（ψ 把接收者钉在链的位置一，任何类型的任何方法都能链）。ψ 放弃的是 nushell 的 shell 身份：没有默认的文件系统与环境上下文，一切走宿主导入。

**Scala** 的核心语义同样是方法调用加多层糖，但 `x + y`、`xs map f`、`for` 由编译器逐条展开成不同目标（`+` 走 `Int.+`、`map` 走隐式转换后的方法、`for` 走 `map`/`flatMap`/`withFilter`），每种糖各管一段。ψ 只有一个展开目标：接收者 + 名字 + arity 个实参的步进链。差别不在糖的多少，在**展开目标有几个**——一个目标，解析规则就能写成四条；多个目标，规则只能随特性乘法增长。

## 被否决的设计

| 设计 | 否决理由 |
|:--|:--|
| 一元方法 + 自动柯里化 | 偏应用产生的函数值在链上没有位置，为它保留一套 arity 饱和规则不值当；多参数写成 arity，函数只有块 |
| 独立的具名函数 | 零参调用没有记号，名字表示值与表示调用同形；要么全语言加记号，要么给零参函数开例外 |
| arity 上限（≤3） | 硬拦参数个数，拦不到散装的根：约束点是接收者必须是聚合，散参数靠句法梯度就够；硬拦会把 `rect x y w h` 逼成仪式化的记录 |
| Python 式装饰器（`f = deco(f)`） | 方法不是值，包装没有落点；要包装就得有宏，而宏把编译时间变成数据相关。装饰器降级为编译期标签 |
| JSONPath 全量（`*`、`..`、过滤） | 通配把「定位」变成「查询」，结果类型随段而变，取值处读不出形状；v1 只做段序列，通配另立 `Query` |
| 种类推断 / 高阶合一 | 调用点必须推断构造子，编译时间与错误质量双输；构造子改由接收者的静态类型给出 |
| 由声明决定的中缀优先级 | 解析器必须读跨模块声明，解析与加载耦合，线性编译破产；改为按首字符定级 |
| 管道运算符 | 与方法链同义，双记法是纯负担 |
| 继承 / `super` / 线性化 | 树模型，且引入派发顺序这一维 |
| LLVM / Cranelift | 把后端复杂度留在语言侧，与「编译快」直接冲突 |
| 自建 GC / 分配器 | 会让「小」破产；wasm-gc 已经把这层下沉到宿主 |
| 宏 / 编译期求值 | 展开轮数不定、能生成声明，编译时间变成数据相关；「多一遍」不是这里的理由 |
| 命名空间树 | 模块是值、import 是绑定，寻址用路径，不需要第二套复用拓扑 |
| 核心 async | wasm 无线程；异步交给宿主句柄 |
| borrow checker | 值不可变 + 无引用，别名问题不存在，这套机制没有对象 |

## 未决问题

- `Text` 的表示：wasm-gc `array (mut i8)` 还是宿主句柄。前者自含、后者免拷贝，取决于字符串操作在脚本里的占比。
- 泛型推导边界：双向检查对方法链上的类型参数够不够，是否需要局部的合一。
- `?` 在链中的位置与错误类型转换的人体工程学。
- 迭代协议的最小集：`each` / `for` 的边界，以及提前退出是否需要。
- 早退 `return`：函数体是表达式，除 `?` 之外是否还要一条直写的出口。
- 模式覆盖：记录模式与数组模式是否进 v1（目前只有字面量、变体绑定、`_`）。
- 部分应用的构造子（`Map<K, _>`）：v1 只有一元构造子能当 `F<_>` 用，二元容器的 Functor 形态未定。
- 装饰器要不要给库留扩展点：现在固定四个；扩成用户可定义就要解禁宏，代价是编译时间不再可预测。
- 字段可见性：`Circle { radius: ... }` 现在外部可构造，parse 产生的值与手搓的值同形。要不要让字段默认模块私有、外部只能走导出的构造函数——这是 Parse, Don't Validate 在语法上唯一的抓手。
- 宏若解禁，载体是什么：编译器已经内嵌 wasm 运行时，宏可以是 wasm 模块，只许生成声明、单轮展开（不迭代就不产生不动点）。
- 通配与递归下降：`*`、`..`、过滤若要，应该是独立的 `Query` 类型（结果从 `Json` 变成 `List<Json>`），不是 Path 的一个段。
- `Json` 的精度与键序：`Num` 只有 Float（> 2^53 丢整数），`Obj` 无序；要不要换成 Int/Float 双变体 + 有序映射。
- `Path` 与 OS 的边界：大小写、`..` 归一化、Windows 分隔符——现在只按段序列处理，渲染归宿主。
- 六个优先级级别对 DSL 够不够用；不够时唯一的替代是在 `trait` 上声明 fixity，代价是解析要读跨模块声明。
- 模块循环导入是编译错误还是留成两阶段初始化。
